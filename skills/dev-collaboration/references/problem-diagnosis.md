# 问题诊断与修复流程

适用场景：排查代码报错、系统异常、性能问题等。

## 工作流程

### 第 1 步：收集信息

在开始排查之前，先收集完整的信息：

1. **错误信息** — 完整的错误堆栈/日志
2. **复现步骤** — 如何触发这个问题
3. **环境信息** — 操作系统、语言版本、依赖版本
4. **最近变更** — 最近的代码提交、配置变更、依赖更新
5. **影响范围** — 是所有用户还是部分用户，是所有环境还是特定环境

### 第 2 步：定位问题

系统化地缩小问题范围：

1. **检查错误信息** — 错误信息通常直接指向问题根源
2. **检查最近变更** — `git log` 和 `git diff` 查看最近的改动
3. **二分排查** — 如果不确定是哪个改动引入的，用 `git bisect`
4. **日志分析** — 检查应用日志、系统日志、访问日志
5. **环境检查** — 确认环境变量、配置文件、依赖版本是否正确

### 第 3 步：分析根因

找到问题的真正原因，而不是表面症状：

- **表象 vs 根因** — "接口超时"是表象，"数据库查询没有索引"是根因
- **单一根因 vs 多因素** — 有时候问题是多个因素共同导致的
- **临时修复 vs 永久修复** — 先止血，再治本

### 第 4 步：制定修复方案

根据根因分析，制定修复方案：

1. **评估影响** — 修复会不会引入新问题
2. **选择方案** — 如果有多种修复方案，选择最安全的
3. **编写测试** — 先写能复现问题的测试
4. **实施修复** — 最小化改动原则
5. **验证修复** — 运行测试，手动验证

### 第 5 步：验证与收尾

- 运行完整的测试套件
- 在测试环境验证
- 监控修复后的系统状态
- 记录问题和解决方案（Issue/文档）

## 常见问题排查指南

### 启动失败

```
检查清单：
1. 端口是否被占用？
   - Windows: netstat -ano | findstr :端口号
   - Linux/Mac: lsof -i :端口号
2. 依赖是否安装完整？
   - npm install / pip install -r requirements.txt
3. 配置文件是否正确？
   - 检查环境变量、配置文件路径
4. 数据库是否可连接？
   - 检查数据库服务状态、连接字符串
```

### 接口报错

```
检查清单：
1. 请求参数是否正确？
2. 认证信息是否有效？
3. 服务是否正常运行？
4. 网络是否通畅？
5. 防火墙/代理是否拦截？
```

### 性能问题

```
检查清单：
1. 数据库查询是否有 N+1 问题？
2. 是否缺少索引？
3. 是否有内存泄漏？
4. 是否有死循环或递归？
5. 是否有未优化的正则表达式？
6. 是否有大文件/大对象未释放？
```

### 依赖冲突

```
检查清单：
1. 是否有版本锁定文件（package-lock.json / requirements.txt）？
2. 是否有循环依赖？
3. 是否有同名但不同版本的包？
4. 是否需要清除缓存重新安装？
   - npm: rm -rf node_modules && npm install
   - pip: pip install --force-reinstall
```

## git bisect 二分排查

当不确定是哪个提交引入了问题：

```bash
# 开始二分排查
git bisect start

# 标记当前版本有问题
git bisect bad

# 标记一个正常的版本
git bisect good <正常的commit-hash>

# Git 会自动 checkout 到中间的提交
# 测试这个版本，然后标记：
git bisect good  # 这个版本正常
git bisect bad   # 这个版本有问题

# 重复直到找到引入问题的提交

# 结束二分排查
git bisect reset
```

## 日志分析技巧

### 查看实时日志
```bash
# Linux/Mac
tail -f /var/log/app.log

# Windows (PowerShell)
Get-Content -Path app.log -Wait
```

### 搜索错误
```bash
# 搜索 ERROR 级别日志
grep "ERROR" app.log

# 搜索特定时间段
grep "2024-01-15 10:" app.log

# 搜索特定请求ID
grep "request-id-xxx" app.log
```

### 统计错误频率
```bash
# 统计各类型错误数量
grep "ERROR" app.log | awk '{print $5}' | sort | uniq -c | sort -rn
```
