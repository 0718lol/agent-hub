### 如果存在认证模块，审查应关注的维度

假设 `src/auth/` 目录存在且包含登录、注册、token 刷新功能，以下是按照代码审查流程应关注的关键点：

#### 1. 安全性（最高优先级）

- **密码存储**：是否使用 bcrypt/argon2 等安全哈希算法？是否设置了合理的 salt rounds？
- **Token 安全**：JWT secret 是否硬编码？token 过期时间是否合理？是否实现了 token 轮换？
- **SQL 注入**：用户输入是否使用参数化查询？
- **暴力破解防护**：登录接口是否有速率限制？是否有账户锁定机制？
- **输入验证**：邮箱格式、密码强度、用户名长度等是否验证？

#### 2. 功能正确性

- **注册流程**：是否检查用户名/邮箱唯一性？是否发送验证邮件？
- **登录流程**：错误提示是否模糊处理（不泄露"用户不存在"vs"密码错误"）？
- **Token 刷新**：refresh token 是否与 access token 分开存储？是否实现了 token 黑名单？

#### 3. 代码质量

- **错误处理**：异常是否正确捕获和处理？是否避免了吞掉错误？
- **职责分离**：路由、服务、数据访问层是否清晰分离？
- **代码复用**：认证逻辑是否有重复代码？

#### 4. 性能

- **数据库查询**：用户查找是否有索引支持？
- **Token 验证**：是否缓存了公钥或使用了高效的验证方式？
