# 遗留系统维护流程

适用场景：维护现有代码库、修复 Bug、升级依赖、重构模块。

## 工作流程

### 第 1 步：代码诊断

深入分析现有代码：
- 阅读相关代码文件，理解模块结构和数据流
- 识别问题根源（不是症状）
- 检查依赖关系和潜在影响范围
- 检查代码质量、类型错误和安全漏洞

### 第 2 步：创建修复分支

```bash
git checkout -b fix/问题简述
```

分支命名规范：
- Bug 修复：`fix/问题描述`
- 重构：`refactor/模块名`
- 依赖升级：`upgrade/依赖名`
- 迁移：`migrate/迁移内容`

### 第 3 步：编写测试

在修改代码之前，先编写测试来重现问题：
- Bug 修复：编写能触发 Bug 的测试用例
- 重构：编写覆盖现有行为的回归测试
- 升级：编写兼容性测试

测试应覆盖：
- 正常路径（Happy Path）
- 边界条件
- 错误处理路径

### 第 4 步：实施修复

在测试的保护下进行代码修改：
- 保持最小化改动原则
- 优先修复核心问题，不做无关重构
- 如果发现其他问题，记录但不在此分支修复
- 每完成一个逻辑单元的修改就运行测试

### 第 5 步：验证

全面验证修复结果：
- 运行完整的测试套件
- 检查是否有回归问题
- 验证性能没有明显下降
- 检查 git diff 确认改动范围合理

### 第 6 步：提交

```bash
git add -A
git commit -m "fix: 简洁描述修复内容"
```

提交信息格式：
- `fix: 修复XXX问题`
- `refactor: 重构XXX模块`
- `upgrade: 升级XXX到vY.Z`
- `migrate: 迁移XXX到YYY`

## 依赖升级专项流程

对于依赖升级，额外注意：

1. **检查兼容性** — 阅读 changelog 和 migration guide
2. **锁定版本** — 更新 package.json / requirements.txt 中的版本号
3. **运行测试** — 确保所有测试通过
4. **检查弃用警告** — 处理所有 deprecation warnings
5. **分阶段升级** — 如果涉及多个大版本，逐版本升级

## 代码迁移专项流程

对于框架或库迁移：

1. **并行运行** — 新旧系统并行运行一段时间
2. **逐步迁移** — 按模块逐步迁移，不要一次性全部替换
3. **数据一致性** — 确保迁移过程中数据不丢失、不损坏
4. **回滚方案** — 每个阶段都要有回滚方案
